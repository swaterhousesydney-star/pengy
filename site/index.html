A night with Pengy

The cap hits at 1:15am.
You find out at breakfast.

Usage windows don't care what time it is. Every other tool stops dead and waits for a human. Here's the same night, twice.

23:40
You hand Pengy the job and close the laptop. "Finish the checkout flow and run the tests."
00:52
Claude finishes the API layer. Codex starts on the tests. No alert — nothing needs you.
01:15
Claude hits its 5-hour cap. Pengy reads the reset time and waits. Still no alert.
01:15 — 03:00
Nothing. This is the part every other tool gets wrong.
03:00
Window resets. Pengy resumes exactly where it stopped.
04:31
The migration needs a decision Claude won't make on its own. Not a cap — so Pengy stops and pings you once.
07:50
One message on your phone. You pick it up over coffee.
Seven hours of work. One notification. No 3am alerts, because you weren't needed at 3am.
What makes it true

Three things, and the first one
is the whole product.

01

It knows every agent's quota

Pengy tracks when each usage window resets, across every vendor you run. On a cap it either waits it out and resumes, or hands the task to an agent that still has budget. Nothing else does this across vendors — the model providers have no reason to help you route around their own limits.

02

It escalates. It doesn't notify.

An alert every time an agent finishes is an app you mute by Thursday. Pengy stays quiet unless something is genuinely blocked, then asks one question you can answer with one tap from anywhere.

03

It operates. It doesn't observe.

Desktop assistants watch your agents and narrate what they did. Pengy picks the agent, writes the prompt, reads the result, and decides what happens next. Watching and operating are not the same job.

Control

On a leash, or off it.
Your call, per agent.

Trust is the entire product, so the settings are two words long and the honest description of each is short enough to read.

On a leash

Default
  • Edits files in the directory you pointed it at
  • Stops at anything needing a decision, and pings you
  • Waits out caps and resumes on its own
  • Runs your agent's own edits-only permission mode

Off the leash

--off-leash
  • Runs commands, installs packages, executes the test suite
  • Keeps going through caps, restarts and failures
  • Hands over to another agent when one runs out of budget
  • Is your agent's own bypass mode — read the line below
Pengy is not a sandbox, and won't pretend to be one. Off the leash passes your agent its own bypass flag. Pengy does not sit between the agent and your filesystem, and it cannot stop an agent that decides to delete something. What it does is refuse to be the thing that surprises you: the default is on the leash, it never invents a prompt you didn't write, and it never guesses a reset time it didn't read. Run it on a git repo.
Where it runs

Your machine. Your keys.
Your agents.

Pengy runs on your own computer and drives the agent subscriptions you already pay for. No API keys, no account, no server, no telemetry — the only network call it can make is a notification webhook you set yourself. It is one MIT-licensed Python file with no dependencies, so reading all of it before you trust it with a night is a realistic thing to do.

If you don't like terminals

There's a window,
and Pengy does the talking.

Typing pengy on its own opens the window — no subcommand to remember. It tells you which agents are ready and which are capped, you type the job in plain English, and it narrates the night back to you, including the cap it's waiting out. On Linux, pengy desktop puts a Pengy icon in your applications menu, so it's a double-click.

Or pengy widget — a small Pengy that floats above every window and stays there. She tells you what the agents are doing at a glance, and shuts her eyes while she waits out a cap.

Runs on your own machine at 127.0.0.1, behind a token generated fresh each launch. No Electron and no dependencies — it's drawn by the standard library.

Also a plugin

Your agent can hand
work to Pengy itself.

Pengy runs as an MCP server, so the agent you're already talking to can check who still has quota and start a job that survives the cap. One line per host — Claude Code, Codex, Gemini CLI, Cursor, anything that speaks MCP.

Then: "check what still has budget and hand the migration to Codex overnight." An agent can't grant itself a bypass mode — jobs it starts run on the leash, and only you can change that.
